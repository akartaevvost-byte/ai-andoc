## Общая информация

| Блок | Содержание |
|------|------------|
| Ссылка на отчёт | |
| Автор отчёта | ФИО, телеграм, почта; команда; тимлид |
| Стейкхолдеры | ФИО, подразделение, почта, телеграм |
| Задача создания | Ссылка на задачу в Кайтен / Я.Трекере |

## Техническое задание

| Раздел | Содержание |
|--------|------------|
| Аудитория отчёта | Кто основной пользователь |
| Текущие проблемы / боли (AS IS) | Что должен решать отчёт |
| Выводы на основе отчёта | Какие выводы из показателей (не решения) |
| Решения | Какие решения принимает заказчик по выводам |
| Формат и период | Частота использования, обновления, глубина по блокам |
| Категории и фильтры | |
| Источники данных | Серверы, таблицы, вью, процедуры, витрины |
| Существующие отчёты | Частичные аналоги |

## Показатели

| Наименование | Бизнес-описание | Алгоритм расчёта | Дата действия | Примечание |
|--------------|-----------------|------------------|---------------|------------|
| | | | | |

Дата действия заполняется, когда меняется логика метрики. У строки со старой логикой в примечании стоит «неактуальна», а в дате действия - день, до которого метрика действовала (`до ДД.ММ.ГГГГ`). У строки с изменённой логикой в дате действия стоит день, с которого она действует (`с ДД.ММ.ГГГГ`).
